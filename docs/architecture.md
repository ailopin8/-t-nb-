# System architecture · ÀTÚNBÍ

## Domain ontology

**Environment** `E_i`: a bounded spatial domain `{0,...,9}³` with exactly 1,000 addressable positions. It holds an internal state, but is not intrinsically an algorithm.

**Algorithm** `F_i`: a transition rule acting on the state of the environment and zero or more input patterns. It may exhibit diffusion, cellular automata, oscillation, reaction-diffusion, transport, or other dynamics.

**Pattern** `P_i(t)`: a spatial or derived observable of `X_i(t)`, produced by an algorithm. A pattern is not necessarily a single scalar; it can be a 3D field, a graph, an event stream, a time series, or a structured object.

**Pattern node** `N_{i,k}`: an exposed, typed output port for pattern `k` generated by sandbox `i`. Nodes identify *what can be connected*, not the entirety of the environment.

**Relationship** `G_{ij}`: a typed and independently configurable transformation from a source pattern to a destination input. The relationship can include filtering, mapping, scaling, transformation, thresholding, time delay and constraints.

**Receiving algorithm** `F_j`: the *already existing* processor in the target environment. Incoming patterns modify its inputs or constraints but do not replace `F_j`.

## Formal update

For sandbox A and sandbox B:

```text
X_A(t) -- F_A --> X_A(t+1)
   │
   └── H_A(X_A(t)) = P_A(t)  [pattern node output]
             │
             ▼
        G_AB(P_A(t)) = U_B(t)  [relationship]
             │
             ▼
X_B(t) -- F_B(X_B(t), U_B(t)) --> X_B(t+1)
```

The example uses a deterministic identity-coordinate mapping between two equal-sized 3D grids:

```text
U_B[x,y,z] = connection_enabled ? connection_strength * P_A[x,y,z] : 0
drive_B[x,y,z] += 1.1 * U_B[x,y,z]
```

This means changes at position `(x,y,z)` in A can change the subsequent activation dynamics at position `(x,y,z)` in B, without discarding B's existing update rule. The coupling operator can later be generalised to nonlocal neighbourhood maps, rotations, convolutions, spectral transforms and delays.

## Experimental validity

The prototype simultaneously evaluates a matched B control whose coupling input is always zero. The differences between coupled B and its uncoupled control are:

- Mean difference of state values.
- Root-mean-square spatial divergence over the 1,000 positions.

When the connection is disabled and the world is reset, these differences must be zero at subsequent steps. With a nonzero connected pattern, divergence is expected to emerge between experimental and control trajectories. Here, *divergence* is evidence of causally effective coupling, not sufficient evidence for emergent system properties.

## Stage-gate scope

- G1: one bounded environment with a dynamically changing pattern.
- G2: two independently evolving and identifiable algorithmic patterns.
- G3: typed pattern output → relationship transform → existing receiving algorithm with measurable local state differences.
- G4: user-authored graph of nodes, edges, multiple patterns per environment, lifecycle and connection validation.
- G5: independent clocks, scheduler, replay, snapshots, import/export.
- G6: explicit emergence observables, baselines, intervention experiments and criteria.
- G7: WebXR controller interaction with the full graph.
- G8: verified plug-in contracts and sandboxed algorithm execution.

## Engineering caveat

Modularisation improves separation of concerns and can permit selective or parallel execution, but does not automatically reduce total CPU/GPU cost. Runtime overhead, update frequency, memory allocation and browser GPU limits must be measured as the number of sandboxes and edges scales.
